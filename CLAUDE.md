## Code style

- Keep files small: about 150 lines or fewer. Split by job (one component, hook or service step per file).
- Name things for what they do, so the code reads without comments.
- Comments are short and only explain a non-obvious reason or a trap. No long comment blocks.
- Help pages and UI text use plain English (the `simple-english` rules): short sentences, active voice, no jargon.
